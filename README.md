### 7,273F版・7,263F版・7,262F版の経緯

- **7,273F版**（`archive/candidate_7273.bk2`）と **7,263F版**（`archive/RomancingSaGa_7263F_BizHawk.bk2`）は、MetaのAIのMuseが作った更新案です。7,273F版はバグ発火前の前半を詰めて6F、7,263F版はさらに追い返しの周期の間の待ちを詰めて10F縮めています。追い返しの区間にはフレームルールがあり、一定以上早くならないと結果に反映されません。
- **7,262F版**は、Claudeが7,263F版の前半から待ちを1F削ったものです。あわせて、前半で浮かせられる待ち（移動の押しっぱなしの長すぎる部分など）を、フレームルールに吸収されても構わない前提で詰められるだけ詰めています。浮いたフレームは、港で船が動く演出や追い返しの周期などで吸収されるため、全体の長さはそれ以上縮みませんでした。A連打の一部を押しっぱなしに置き換えた箇所がありますが、結果は同じです。

### 7,290F版・7,279F版の制作者と手法

7,290F版と7,279F版は、ChatGPT（dot）ではなく、**AnthropicのAIアシスタントClaude**が作成・検証しました（2026年10月23〜24日）。それ以前の版と研究報告（`ロマンシング サガTAS制作研究報告.mhtml`）はChatGPT（dot）によるものです。

- バグ発火後、slot 11の命令ポインター上位バイトはタイマーと重なっており、毎フレーム1ずつ減ります。ボタンを押した時刻によって、次にROMのどこをイベント命令として読むかが決まります。
- Claudeは、BizHawk 2.11.1のBSNESv115+コアを直接呼ぶ計測ホストを作りました。これを使い、7,198F時点の待ち状態から「各待ちで何フレーム目に何を押すか」を総当たりする最良優先探索を行いました。
- 多くの待ちではどのボタンを押しても結果は同じですが、一部の待ちではXを押すとAと違う位置へ進みます。7,279F版はこの違いを使っています。
- 見つかった経路は次のとおりです。7,197F目までは7,325F版と同一です。

| 版 | バグ発火後の押下（入力の行番号、0始まり） | エンディング入口 |
| --- | --- | ---: |
| 7,325F版 | A: 7214, 7233, 7295, 7324 | CPUフレーム7,324 |
| 7,290F版 | A: 7214, 7224, 7241, 7265, 7289 | CPUフレーム7,289 |
| 7,279F版 | A: 7215, 7218, 7221, 7227, 7235 → X: 7244, 7255 → A: 7278 | CPUフレーム7,278 |

- 探索の経緯
  - 1回目（A単押しのみ）：最初の押下時刻126通りすべてを調べ、計21,156状態を展開しました。この条件ではCPUフレーム7,289が最良でした。
  - 2回目（A・X・Y・B単押しと「A後にB押しっぱなし」）：7,289未満を上限に再探索して7,278の経路を見つけ、Y・Bは途中から試す対象から外しました。最初は5種類で始めましたが、事前の比較でYとBの単押しはAと同じ結果しか出さなかったためです。その後も7,278を上限に全区間を調べ終え（計17,778状態を展開）、CPUフレーム7,278より早い経路は見つかりませんでした。
  - 3回目（連続フレームの押下を追加）：Aを押した直後のフレームでも新しい押下にできるよう、B・X+Bなど別のボタンで押す行動を加え、7,278未満を上限に全区間を再探索しました（計11,898状態）。CPUフレーム7,278より早い経路は見つかりませんでした。
  - 同時押しや押す前の入力履歴の影響：ランダムな状態とランダムな入力列で計約1,600通りを比べました。結果は、ほぼすべて「新しく押されたフレーム」と「Xを含むかどうか」だけで説明できました（AとBを交互に使って連続押下を再現した場合、534通り中533通りが一致）。一部の待ちではYやSelectでは抜けられませんでしたが、短縮につながる副作用は見つかっていません。
  - 同じ状態かどうかは、イベント記録の一部（命令位置の下位バイト・終了位置・タイマーの位相）で判定しています。探索の結果は条件内のものであり、最短性の証明ではありません。
- 追い返しループ（約5,299〜7,180F）の各Aは、1F早めるとどれも失敗することも確認しています。冒頭の無入力区間（325〜1,427F）は、どのボタンでも進行が変わらないことを確認しています。バグ発火直前（7,170〜7,198F）にA以外の入力をしても、最初の待ちの状態は変わりませんでした。

## ファイル名の読み方

例：`RS1_BizHawk_tail_search_7290F_verified.bk2`

- `RS1`：ロマンシング サ・ガ
- `BizHawk`：使用エミュレーター
- `tail_search` など：試行や調整内容を区別する識別子
- `7290F`：入力ログのフレーム数
- `verified`：検証済みとして保存したファイルの識別子。個々の検証条件がすべて同じという意味ではありません。
- `.bk2`：BizHawkのムービー形式

`verified` がない旧版も保存しています。名前だけで再生可否を判断せず、通常は上の最新・最良版を選んでください。
