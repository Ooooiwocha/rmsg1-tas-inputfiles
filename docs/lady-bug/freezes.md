# レイディバグ中の「止まって見える状態」の分類

バグ発火後、何を押しても進まないように見える状態を、裏で何が起きているかで分けたものです。
検出は `ladybug-tools.lua`／`freeze-detect.lua` で行えます。

調べ方：BizHawk 2.11.1（BSNESv115+）のステートから、プログラムの実行位置・呼び出し元・
作業用RAMの変化・全ボタンへの反応・3,000フレーム放置の結果を見ています。

## 1. 本当のフリーズ（どの操作でも抜けられない）

入力を読む処理に戻らないので、ボタンの組み合わせを試す意味がありません。

| 型 | 止まっている処理 | 終わらない条件 | 見分け方 |
|---|---|---|---|
| 窓の行送りループ | 窓に文字を書くとき、「行番号（$160F+Y）が窓の高さ（$1606+Y）以上なら1行送って行番号を1減らす」を繰り返す（$00:A45C〜、$00:C752〜） | 窓の高さが 0 | ループ本体 $00:A464／$00:C75A に来たとき $1606+Y が 0 |
| 選択肢の窓の送りループ | 選択位置（$12CC）が見えるところまで、下端の行番号（$1618+Y）を2ずつ増やして一覧を送る（$00:BD8F〜） | $12CC が $FF（または $FE で行番号が偶数） | ループ本体 $00:BD97 に来たときの $12CC |
| 割り込み停止中のフレーム待ち | 「次のフレームまで待つ」処理（$00:8936〜）。合図 $1206 に 1 を書き、割り込み処理が 0 に戻すのを待つ | 割り込みが止められたまま待ちに入った | 入力を読まないフレームが続く（ムービーでは最長37）。作業用RAMが一切変わらず、タイマーと重なる12枚目のメモも止まる |

| 暴走 | プログラムがRAMの中（$00:0000 付近など）を実行し、スタックの位置がメモリ全体を動き回ってRAMを壊し続ける | 確認した例の原因：オブジェクトを子ごと削除する処理（$02:84E2、データは $7F）が自分自身を呼び出す作りで、親子のつながりが輪になっていた（$7F:060F の子が $7F:20FF、その子が $7F:060F）ため呼び出しが終わらず、1回ごとに8バイトずつスタックが伸びてRAMを上書きした。つながりが輪になった理由は未特定。このほか、ランダム試行と狙った探索で集めた暴走は、範囲を確かめずに表を引く処理が原因だった（命令 `40` の次のバイトが範囲外／命令 `1E` が呼ぶ処理スクリプトの番号がでたらめ／処理スクリプトの中の命令が範囲外）。ランダム試行で見つかった「バンク$02の処理から戻るときに飛ぶ」型は、調べ直すと上の $02:84E2 の型と同じだった（処理スクリプトの3番の命令が $02:8034 を呼び、オブジェクト $7F:FF20 の子が自分自身を指していた）。$02:C836 からRAMへ飛ぶのは、スタックの上に書いたブロック転送を実行する正常な処理（$02:C7EC〜）。見つかっている最速は7,256F（Aを 7209・7224・7244・7253・7256）、最少の操作は7,713FのA1回。くわしくは解説記事の10章「処理スクリプトと暴走」 | フレームの切れ目の実行位置がRAMにある状態が続く（ムービーでは1回もない）。画面は真っ暗になり、入力を読まないフレームが続く |

補足：

- 選択肢の窓の送りループには、フレームを待たずに回る出方（1フレームに約460回）と、
  1行送るたびに画面更新を待つ出方（2フレームに1回）の両方がある。
- 命令 `14 n` は n×2 フレーム待つ。n が 0 のときは約65,000フレーム（約18分）待つので、
  実質フリーズに見えるはず（実例は未確認）。

## 1.5 入れ子の途中でのイベント終了（`40 4B`）

港で追い返されるたびに、「イベント → フィールド側の命令 → イベント」という呼び出しが1段ずつ深くなる。
その途中で副命令 `40 4B`（メモを全部捨ててイベント終了）を読むと、メモは1枚目に戻り、
呼び出しの入れ子は1段だけ戻る。追い返しのスクリプト自体が `40 4B`（$1B:D6C3）で終わるので、
残っているメモに戻ったときにも起きる。

そのあとどうなるかは場面しだいで、行き止まりとは限らない。

- 直後に止まる例：$1C:81A6 の `40 4B`（「ニーサに祈る」のセリフのあと、`06 1B` に続く）は、
  割り込みが止まったままのフレーム待ちに入りやすい。操作不能のまま回り続ける例、
  約300フレーム後に暴走する例も確認した。
- 進み続ける例：`40 4B` を何度か通るたびにスタックの位置が浅くなり（$1D14 → $1D47 → … → $1DF3）、
  1枚目で港のスクリプト（$1B:D6xx）を読み続ける。

下の試行では、4,000フレームたっても進み続けていた26回は、すべてこの `40 4B` を通っていた。
通らなかった121回は、全部がフリーズ・暴走・無反応で終わった。

見分け方：`40 4B` の処理（$00:B861）に来たときのスタックの位置。正常な場面では $1EE8 付近、
入れ子が残っていると $1Dxx 以下。`ladybug-tools.lua` は `NESTED END` と表示する。

## 1.6 12枚目のステートからのランダム試行

12枚目を読んでいる最中のステート7個（うち2個はほぼ同じ場面）から、ボタンをランダムに押して進めた198回の結果。
1回の試行は最長4,000フレーム。押し方は「Aだけ」「AとX」「カーソル多め」「全ボタン混ぜ」。

| 結末 | 回数 | 割合 |
|---|---|---|
| 選択肢の窓の送りループ | 77 | 39% |
| 窓の行送りループ | 47 | 24% |
| 暴走 | 36 | 18% |
| 4,000フレームたっても進んでいる | 26 | 13% |
| 入力を読まないフレームが続く（割り込み停止など） | 6 | 3% |
| 1,500フレーム命令を読まない | 6 | 3% |
| エンディング | 0 | 0% |

- 止まるまでのフレーム数は、中央値で約320フレーム。4分の1は60フレーム以内。
- 選択肢の送りループの直前に読んだ命令は `17`、`34`、`3C`（どれも選択肢の窓の命令）。
- 暴走36回のうち13回は、$1A:EC21 のフィールド側の命令 `04` の直後。
- 押し方ごとの「進み続けた」割合：Aだけ 19%、AとX 19%、全ボタン混ぜ 12%、カーソル多め 7%。
  選択肢の送りループに入る割合は、押し方によらず35〜42%だった。
- ほぼ同じ場面の2個からは、58回中49回が同じ場所（$17:F232 の `17`）で選択肢の送りループに入った。
  全体の割合は、この2個に引っぱられている。

## 1.7 嵐のイベントへ流れ込んだあと

`40 4B` を通ってメモが1枚目に戻ると、読み取り位置は $1B:D6C3 の次、嵐から沈没までのイベント
（$1B:D6C5〜、「もうすこしで ○○だ！ もちこたえろ！」「いままでありがとよ レイディラック！」）に進む。

12枚目のステート6個から、A・Xだけを押して最長15,000フレーム進めた72回の結果：

| 結末 | 回数 |
|---|---|
| 選択肢の窓の送りループ | 20 |
| 窓の行送りループ | 19 |
| 15,000フレームたっても進んでいる | 14 |
| 暴走 | 13 |
| 割り込み停止など | 3 |
| 1,500フレーム命令を読まない | 3 |

- 嵐のイベントの中まで読み進めたのは16回。そのうち10回は、イベントの最後の `40 4B`（$1B:D7E1）付近まで届いた。
- 届いたあとのスタックの位置は $1EF1〜$1F12 で、正常な場面（$1EE8）より浅い。入れ子をほどきすぎている。
- そこから7回が $1A:E19B 付近で窓の行送りループ（フリーズ）に入った。
- 進み続けた14回のうち8回は、$1A:E536〜E538（`40 5E`、`40 30`）を何度も読み直す状態だった。
  スタックの位置は $1C8x〜$1EEx とまちまちで、正常に戻ったとは言えない。
- 本来のゲーム進行（普通に操作できる状態）に戻ったと確認できた試行はない。

## 2. 止まって見えるが、放置すれば進む状態

入力を読まずに時間だけが過ぎる状態です。この間はボタンを押しても何も変わりません
（ただし12枚目のメモはタイマーと一緒に進むので、経過フレーム数は後の行き先に効きます）。

| 状態 | 最後に読んだ命令 | 観測した再開までの時間 |
|---|---|---|
| フィールド側の処理の実行中 | `0F`、`06` | 76〜222フレーム |
| 窓の文字表示・行送りの途中 | `13` | 89〜114フレーム |
| 時間待ち | `14 n` | 83〜194フレーム |

## 3. 入力を待っている状態

| 状態 | 命令 | 効く操作 |
|---|---|---|
| Aボタン待ち | `12` | A（Xも効く場面がある） |
| 行き先を選ぶマップ画面 | `0D n` | カーソルで行き先を変える。カーソルのあとにA、またはBでマップが閉じて再開する。Aだけだと別のマップに切り替わる場合がある |

## サンプルでの割合

バグ発火後にA・Xを適当に押して進め、50フレーム何も起きなくなった状態58個の内訳：

| 分類 | 個数 |
|---|---|
| AかXで進む | 25 |
| マップ画面（入力待ち） | 12 |
| 放置すれば進む | 18 |
| 本当のフリーズ | 3 |

サンプルが小さく、A・Xだけで進めた範囲なので、割合は目安です。
